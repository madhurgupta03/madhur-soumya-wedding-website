## Workflow

Run everything from the `Wedding_Stationary` folder. On Windows use `python`; on macOS/Linux use `python3`.

```
python Source/make.py all      # full rebuild from the PDF: extract → glyphs → build → og → check
python Source/make.py build    # after editing Source/pipeline/build.py (makes index.html and test.html)
python Source/make.py check    # automatic checks; must end with "ALL CHECKS PASSED"
python Source/make.py serve    # preview at http://localhost:8000 (or double-click Website/Open website.bat)
python Source/make.py og       # refresh og-cover.jpg after changing the cover
python Source/make.py video    # optional: Previews/Envelope-opening.mp4
```

**Normal change loop:** edit `Source/pipeline/build.py`, then `make.py build`, then `make.py check`, then look at it with `make.py serve`. If you changed the CHANGES list or features, update `Guides/CHECKLIST.md`. Then deploy.
`extract` and `glyphs` only need re-running if the PDF itself changes.

**Never hand-edit `Website/index.html`.** It is overwritten on every build. Make every change in `build.py`.

## How the build works (so edits land in the right place)

- **Card pages 1–8** are SVGs, one per PDF page, in a 810 × 1440 viewBox (1 unit = 1 PDF point):
  - The artwork is drawn with the PDF's own images at their exact transform matrix and opacity, in the PDF's paint order. The PDF's own vector ornaments (for example the gold Ganesha on page 2) are copied too.
  - **Unchanged text** is drawn with the PDF's own letter outlines (`<use href="#pN_font_…">`) at the exact PDF positions, so it matches the PDF even for Canva-only fonts.
  - **New or restyled text** (parent names, venue lines) is live `<text>` in **Crimson Text**, the free version of the PDF's Crimson.
- **Website sections** between the cards (`venues`, `rsvp`, `blessings`, `blessings-groom`) are normal HTML inside the `EXTRA_SECTIONS` string.
- **Page order:** cover, invitation, Tilak, Engagement & Sangeet, Haldi & Mehendi, Baraat, Jaimala → Where we celebrate → RSVP → Bride's side → Groom's side → closing page.

Where things live in `build.py` (search for these markers):

| To change… | Look for |
|---|---|
| Parent names, spacing amounts, venue size, small "&" size | `# ---------------- decisions agreed with the user` (`PARENTS`, `NAME_SHRINK`, `HINDI_TRACK_CUT`, `VENUE_SIZE`, `SMALL_AMP`) |
| Google Maps links | `MAPS = {` |
| Event titles, title-to-date gap, venue text, directions buttons | `# ---------- event pages:` |
| Names under the cover monogram | `# ---------- page 1:` (`COVER_SCALE`, `COVER_GAP`) |
| Venue cards, RSVP form fields, blessings lists | `# ---------- website sections` (`bride = `, `groom = `, `EXTRA_SECTIONS`) |
| Styles | inside `page = f"""` → `/* website sections`, `/* envelope intro */`, `/* RSVP form */`, `/* blessings */` … |
| Envelope animation | `/* ---------- envelope intro:` |
| Falling flowers and sparkles | `/* ---------- falling petals` |
| Countdown date | `/* ---------- countdown` |
| Google Form connection | `var GOOGLE_FORM = {{` |

`build.py` builds the page with Python f-strings, so **every literal `{` or `}` in CSS/JS must be doubled** (`{{ }}`). A regex like `\D` must be written `\\D`.

## Rules from the owner — do not break these

1. **Copy the approved PDF exactly** (`1_ORIGINAL_approved_design.pdf`): same colours (exact hex values from the PDF), positions, alignment, margins, spacing, fonts and every word, including **"॥ श्री गणेशाय नमः ॥"**. Change only what `Guides/CHECKLIST.md` lists.
2. **Artwork is approved as-is.** Never screenshot, compress, crop, stretch, recolour or regenerate it. It comes only from `extract.py`. Animations may move things *around* the artwork, never the artwork itself.
3. **No placeholders and no design ideas of your own.** If something is unclear, ask Soumya before changing it. Don't guess.
4. **Website sections** (venues, RSVP, blessings) must stay readable at the same size as the card pages: body text about 16–18 px on a phone, using the card's colours (#784646 brown, #b85c1d rust, #fdf5ef paper, gold #c99a3e, night blue #1d2f5c).
5. **A reload always starts from the envelope** at the top.
6. Run `make.py check` before handing anything over, and look at the result yourself.

## Deploying

The `Website` folder is a static site with no build step on the server.
- **vercel.com:** open the existing project, drag in the `Website` folder (or connect a Git repo with `Website` as the root).
- **CLI:** `cd Website` then `vercel --prod`. `.vercelignore` keeps `test.html` and the `.bat` file out.
- After deploying, open the live link on a phone, go through the envelope and all pages, and check the WhatsApp preview by pasting the link into a chat.

## Going back to an earlier version

Earlier versions of `build.py` are in `Archive/earlier-build-versions/`. They use the old scratch-folder paths, so don't run them as they are: copy the part you need (for example an earlier envelope animation) into the current `Source/pipeline/build.py`, then build and check. If the folder is under Git (it is), `git log` and `git diff` also show past states.

## Known limitations / open items

- Alta (title font) and Amoresa (script font) are Canva fonts. The site uses their letter shapes from the PDF only for text already in the PDF. New words in those fonts need the font files plus a licence check.
- The artwork totals about 22 MB (lossless, as the owner required). It loads page by page (lazy loading); only the first two pages load up front.
- No background music yet. If Soumya supplies a song, add a tap-to-play button, since browsers block autoplay.
